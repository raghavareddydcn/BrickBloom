# Feature Specification: Invoices And Billing

**Status**: Reverse-engineered from current implementation

**Scope**: Admin staff create and manage invoice documents, calculate displayed taxes/totals, print or export documents, and adjust stock through the React invoice workspace.

## User Scenarios & Testing

### User Story 1 - Create and issue an invoice (Priority: P1)

An authorized workspace user enters invoice/customer and line-item information, reviews totals, saves, and prints or exports the document.

**Independent Test**: Create an invoice with inventory and non-inventory lines, save it, then print and export it.

**Acceptance Scenarios**:
1. Given invoice details and line items, when the user saves, then the invoice is stored in Firestore and invoice/stock audit operations are attempted.
2. Given a saved invoice, when the user edits, duplicates, searches, or deletes it, then the workspace applies the corresponding invoice operation and stock delta behavior.
3. Given an invoice, when the user prints or exports it, then the workspace produces the currently implemented A4 print or PNG output.

### User Story 2 - Review billing totals (Priority: P1)

Staff review price tiers, tax, discount, balance, and period summaries while preparing invoices.

**Independent Test**: Exercise quantities at available tier thresholds and inspect invoice tax and period totals.

## Requirements

### Functional Requirements

- **REQ-001**: The workspace MUST support invoice creation, editing, duplication, search, save, print/export, and deletion actions currently exposed.
- **REQ-002**: Invoice numbering MUST follow the current financial-year sequence when generated by the workspace.
- **REQ-003**: Invoice item changes MUST adjust inventory by the net quantity delta for inventory products; deletion MUST restore the deducted quantity.
- **REQ-004**: The workspace MUST support catalog-derived and custom line items and display its current pricing, discount, tax, and balance calculations.
- **REQ-005**: Legacy `bb_invoices` browser data MUST be handled by the existing migration path when it is present.

### Key Entities

- **Invoice**: Customer, date/number, line items, pricing, tax, discounts, and balance fields persisted by the workspace.
- **Invoice line**: Product, quantity, unit price, and applicable tax fields.
- **Inventory product**: Stock record affected by invoice line deltas, excluding non-inventory charges.
- **Audit event**: Invoice action metadata written to the configured audit destinations.

## Edge Cases

- Visible validation does not clearly require a customer or at least one item; stock can become negative.
- The rendered tax summary labels GST as CGST/SGST despite place-of-supply fields; an IGST rendering branch was not apparent.
- Cart handoff names/prices can differ from invoice catalog names/tier prices.
- The React invoice workspace uses Firestore collections (`invoices`, `products`, `counters`, `audit_logs`). The Express JSON invoice API is separate and has no discovered frontend consumer.
- Audit logging failure must be checked independently from invoice/stock mutation; current behavior is implementation-specific.

## Success Criteria

- **SC-001**: A staff user can save, retrieve, edit, and delete an invoice through the React workspace.
- **SC-002**: Invoice edits apply only the net stock delta, and deletion restores the prior deducted quantity for inventory lines.
- **SC-003**: Printed and exported output contains the same invoice number, lines, and totals displayed at export time.
